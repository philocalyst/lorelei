## Since report 1

* Merged the integration branch again (`Row` became an `unsafe trait`: the three new impls carry their
  arguments).
* **A turn that wrote only bound words is not described.** Mutable borrows of signals are counted per thread
  (`signal::writes`); the typed path compares the count of a turn with the block words that changed. Equal and
  non-zero: the block's compare accounts for the whole turn, so it settles. Otherwise (a signal that is not a
  word, a write of the same value, author code that wrote no signal) the view is described, as the façade's
  contract says.

  **A hole, stated:** a handler that writes a bound word *and* a plain field the view reads has equal counts and
  is not described; the plain change shows at the next description. Closing it soundly needs to know that a view
  has no plain state (reflection over its fields at admission) or a rule that state the view reads is a signal.
  That is a decision about the author's contract and is the owner's; until it is made the hole stands and
  `typed_words` pins the neighbouring cases (a plain-only write is described; a same-value write is described).

The scroll cell is still 23,642 and not a few hundred: a pass after a turn runs the view and converts its fixed
part (8,729, measured) to reach the list, then converts the row that entered. In the basis where a scroll is one
word, the list is reached without the view (the row source is kept by the store, as a relation is), and that is
the same move as the keyed relation the insert cell needs.

What prevents each remaining cell, in the representation as it stands (the bases are in report 1's table):

* **Title, theme:** each is a description (115,957 for an unchanged view). The title is a `String` (no word);
  the theme is a plain field. Neither has been given a word: the run handle for the first, a palette slot under a
  broad word for the second (`World::broad` is now in the tree and unused by the prelude).
* **Hover:** a dynamic operand's `READS` is every application word, so the hover word differentiates every
  column that holds a bound colour (about 9 per exposed record). The equality index (`sel`) makes it two records.
* **Insert:** the list is rows by index with no journal; every exposed row is compared and found to be another.
* **Hover + frame:** the reference compositor repaints 32 px tiles on one thread; the legacy runtime's executor
  does not spend CPU instructions on it. This lane has no executor seam to the paint lane yet.
